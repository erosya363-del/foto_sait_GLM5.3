## ЗАЩИТА ОТ ОТКАТОВ (новое, по просьбе пользователя)

| Компонент | Что делает |
|-----------|-----------|
| `scripts/snapshot.sh "метка"` | **Единая точка фиксации шага**: git commit + тег `snap/v1.5-метка` + зеркало в sait_copy_1 + tar-снапшот в download/ + копии документации в download/logs/ + INDEX |
| `scripts/restore_snapshot.sh <файл>` | Восстановление из любого снапшота одной командой (распаковка → install → prisma → build → запуск :3000) |
| `scripts/restart.sh` | Надёжный перезапуск :3000 (убивает по порту через ss; lsof слеп, pkill не берёт next-server) |
| `download/snapshots/` | **Единственная зона, переживающая откат песочницы.** Каждый tar = исходники + db + .env + .git (вся история) + документация |
| Git | Чистая история с чистки: 196МБ → 13МБ (выкинуты 114МБ tarball в истории, системные skills/, видео upload/); снапшот включает .git → восстановление возвращает и историю |

**Правило: после КАЖДОГО шага — `bash scripts/snapshot.sh "<метка>"`.** Снапшоты: 001 (base), 002 (protection-v2), 003 (step5), 004 (step5-docs), 005 (pill-nav), 006 (liquid-v2-header-admin), 007 (shag6).

### КРИТИЧЕСКИЙ ФИКС: загрузки уничтожались ребилдом (найден при Шаге 5)
Standalone-сервер Next.js делает `chdir` в `.next/standalone` и кэширует список public-файлов
на старте. Итог: загруженные файлы писались в копию сборки → 404 без рестарта → стирались
при каждом `bun run build`. Фикс:
1. `src/lib/paths.ts` — корень проекта из DATABASE_URL (абсолютные пути, chdir не страшен)
2. `src/app/uploads/[...path]/route.ts` — раздача файлов напрямую из `<проект>/public/uploads`
3. Проверено: upload → сразу 200 → **полный ребилд → файл жив (200)** → purge → 404
